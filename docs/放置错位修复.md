# 放置错位修复

## 原因与复现

准备棋盘点击格按百分比定位，棋子却用缓存像素格宽计算 transform。旧 fitBoard 使用了包含容器内边距、棋盘边框的外部尺寸；Flex 还可能继续压缩棋盘，导致算出的格宽和实际格宽不同。窗口或布局改变后，缓存像素定位也不会自动跟随。

自动复现中，右侧第八列棋子与点击格最大偏差约 22.75 像素。

## 修复

- 准备棋子与点击格使用完全相同的百分比坐标系，不再依赖缓存像素定位。
- 尺寸计算使用 CSS 布局尺寸，扣除容器内边距与棋盘边框。
- 禁止准备棋盘被 Flex 再次缩窄。
- 缩放、布局变化时，棋子自动随格子对齐，不必等待服务器下次更新。
- 普通动画演示和特效演示已同步更新。

没有修改卡牌数值、战斗规则或商店概率。

## 验证

`python3 tests/test_placement.py`

覆盖初次放置、四个边角与中间格、1000×700、390×844、844×390、1440×960、125% 缩放、无需数据更新的布局变化，以及布局变化后继续放置。8 类测试中，棋子外框与对应点击格的边界偏差均为 0 像素（本测试浏览器环境）。

特效回归、在线动画回归、报告与数据一致性校验也通过。

## 更新方法

建议解压新的 `OI-chess_最新版.zip` 到新文件夹，双击 start.bat 启动。已有对局应先正常退出；浏览器使用 Ctrl+F5 强制刷新。

若保留旧目录，只需替换 static/script.js 和 static/style.css；离线预览也应使用新包中的版本。服务器 Python 源码未修改。


## 第二轮修复：grid-align-2

上一轮只检查了棋子外框和点击区域，未检查背景网格与可见边框，验证范围不足。

本轮改为背景层、点击层、棋子层共享同一 CSS Grid 行列，准备阶段取消缩放/位移入场效果，使用不撑大格子的内描边。测试同时比较背景格、点击格、棋子外框和可见卡面边框，在包括极窄横屏在内的八类场景中均测得 0 像素边界误差。

战斗中的初始定位、缩放重排与插值也统一了坐标方式，特效中心直接从真实背景格测量；五种视口的静止棋子与格线误差、特效中心误差均通过 0.1 像素阈值测试（最大约 0.0005 像素）。移动中的棋子仍按设计在格子之间平滑插值。

资源链接已加版本参数；页面左侧显示“界面版本 grid-align-2”。若看不到这一行，说明仍在访问旧界面，请关闭旧服务器并从新文件夹启动，然后 Ctrl+F5。
