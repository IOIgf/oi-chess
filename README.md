# OI-chess 最新版

**当前界面版本：update-check-1。** 背景格线、点击格与棋子已统一为 CSS Grid（详见 `docs/放置错位修复.md`）；此前已修复半屏布局遮挡与商店卡片显示不全，并把卡牌从 35 张扩到 **50 张**、加入 6 种全新战斗机制与商店升星保底。本轮新增**启动前检查更新**：`start.bat` 与浏览器端都会在启动时静默检查 GitHub 是否有新 Release。CSS 与 JS 缓存版本均已同步为 `update-check-1`，更新后浏览器请按 Ctrl+F5 强制刷新。

## Windows 启动

1. 完整解压文件夹，不要直接在压缩包中运行。
2. 双击 **`start.bat`**。
3. 如果需要手动启动，在本目录打开终端，执行：

```bat
py -3 server.py
```

也可以使用已确认指向 Python 3 的命令：

```bat
python server.py
```

建议使用 Python 3.10 或更新版本。游戏运行只使用 Python 标准库，不需要先安装其他依赖。启动后按终端提示访问网页。

**Windows 编码修复已合入：** 根目录 `server.py` 仅含 ASCII 字节，中文以 Unicode 转义保留，运行时正常显示中文；与实战测试源码的语法树一致。不要从聊天中复制整份源码，也不要运行 `audit/before/` 内的历史备份。

## 当前版本关键数值

- **O2 优化**：$3、攻击 0、生命 **280**；周围八格友军攻速 **×2**，同名不叠加。
- **SPFA**：$3、攻击 **120**、生命 **1000**；攻速 ×1.5、普攻伤害 ×1.2，每次普攻后独立 20% 概率额外停攻 4 秒。
- **升星**：3 张同名同星棋子自动合成，最高 3 星；生命/攻击每星 **×1.8**（3 星 ×3.24）。2/3 星卖出返还 3/9 份金币再减 1，合成后满血。光环类效果不随星级增强，同名光环始终不叠加；升星只提高生命与攻击，O2 优化攻击 0 升星后仍为 0。
- **商店与卡池**：每轮第一次刷新免费，第二次 **2 金**，之后每次 **+1 金**（2/3/4…），棋子本身价格不变。卡池按等级解锁费用（等级 L 可出 1–L 费，低费权重更高；等级 1 仍是纯 1 费，与旧版一致）；每轮结算赠送的一张卡同样从当前等级卡池抽取，不再开局白送 5 费核心。等级每两轮 +1，第 9 轮达到 5 级；差一张即可合成的卡在商店与赠送卡中权重 ×4（升星保底），缓解 50 张卡池的稀释。
- **小轮结算**：阵亡棋子不再消失，保留到下一轮并按原有恢复规则复活；按双方存活棋子的星级之和判定胜负，败者 HP 减少双方星级之和的差，HP 归零即出局。
- 攻击采用精确事件计时，不再将普攻间隔向上取整到 0.5 秒。
- **状态轮询**：请求携带版本号，房间版本与聊天版本均未变时服务端只返回计时字段（8 人满编全量约 3.5 KB，瘦响应约 190 B），心跳与倒计时精度不变；版本或聊天一变立即回退到全量快照。
- **半屏布局**：FX / 主题 / 退出按钮改为顶部独立工具条，不再浮在商店与状态栏上；窄屏状态栏固定属性条宽度并隐藏版本号小字，矮屏自动压薄聊天区把高度还给棋盘；战斗棋盘从首帧即为合并 8×8，杜绝半场被裁；商店卡宽自适应并给列表加明确的细滚动条，窄屏商店行固定高度避免把棋盘压没。8 视口 × 3 阶段由 `tests/test_layout.py` 回归。
- 已完成全卡机制核对、九张卡数值调整、实战定位与清晰特效更新；此前补上按等级解锁的卡池与半屏布局修复。本轮新增 15 张算法卡、6 种战斗机制与升星保底，全池实战数据已按 50 张卡重跑。

## 新增卡牌与战斗机制

卡池由 35 张扩到 **50 张**，新增 15 张算法主题卡（1 费 3 张、2 费 4 张、3 费 4 张、4 费 2 张、5 费 2 张），并新增「图论 / 字符串 / 博弈」3 个流派标签，共 16 类。所有新卡沿用 ASCII-only 的中文转义，卡面描述与战内结算一致。

新增 6 种战斗机制，**只作用于新卡**，旧 35 张卡的结算不变：

| 机制 | 类型 | 效果 |
|---|---|---|
| 穿透 `pierce` | 被动 | 普攻命中后，对目标正后方同列相邻敌人追加 50% 伤害 |
| 溅射 `splash` | 被动 | 普攻对目标上下左右相邻敌人各造成 35% 伤害 |
| 汲取 `lifesteal` | 被动 | 普攻按实际伤害 30% 回复自身，不超过生命上限 |
| 背水 `rampage` | 被动 | 自身生命低于上限 50% 时攻击 ×1.6 |
| 协同 `synergy` | 被动 | 入场时每有一名同流派友军，攻击 +12%（最多 4 层） |
| 冻结 `freeze` | 主动 | 射程内全体敌人受 40% 伤害并停攻 2 秒 |

「协同」把同流派构筑变成实际收益，但没有做成全局羁绊系统：全局加成会改变所有历史卡的对局结算，使 `audit/baseline/` 与 `audit/final/` 的数万场基线失去可比性，属于需要单独重跑并重写报告的更大重构。新卡专属协同既提供阵容构筑维度，又保证旧卡与既有精确时序合同不受影响。

前端同步新增汲取回血的绿色浮字与 6 种新技能的施法标签；商店与赠送卡的保底权重由 `tests/test_shop_pool.py` 抽样验证（差一张合成时该卡出现频率提高 2 倍以上），无玩家上下文时卡池分布与旧版完全一致。


## 检查更新

每次通过 **`start.bat` 启动前**会先运行 `check_update.py`，对比 GitHub 上的最新 Release；浏览器打开主菜单时也会静默检查一次（同一会话只查一次）。发现新版本时，终端打印发布页与下载链接，主菜单顶部出现一条可关闭的提示条。

设计约束：

- **只提示，不自动下载、不覆盖文件**。自动更新会破坏交付包的可复现性，也可能碰到玩家存档 `data/`。
- **离线优先**：默认 2.5 秒超时（浏览器 4 秒），DNS 失败、超时、限流、JSON 异常一律静默跳过，退出码恒为 0，绝不阻塞启动。
- **不参与轮询**：检查只在启动时执行一次，与每 300ms 的 `/api/state` 瘦响应完全解耦。
- **版本真相源**：本地 Release 版本写在 `static/index.html` 的 `<meta name="oi-chess-release">`，`check_update.py`、`版本清单.json` 的 `release_tag` 与浏览器端都从这里读取，由 `tests/test_update_check.py` 断言一致。
- **版本号比较**：只比较 `vMAJOR.MINOR.PATCH` 的前三段数字；远程严格大于本地才提示。本地是开发版（比远程新）或同版本不同构建都不误报。

| 环境变量 | 作用 |
|---|---|
| `OI_CHESS_SKIP_UPDATE=1` | 完全跳过启动器检查 |
| `OI_CHESS_UPDATE_TIMEOUT=2.5` | 调整网络超时（秒） |

直接执行 `py -3 server.py` 会跳过终端检查（浏览器端仍会检查），官方入口仍是 `start.bat`。手动检查可运行 `py -3 check_update.py --json`，输出机器可读的状态字典。

| 文件或目录 | 用途 |
|---|---|
| `server.py`、`start.bat` | 当前唯一启动入口 |
| `static/` | 游戏网页、样式和特效 |

| `特效预览.html` | 离线真实战斗演示，支持主题和低特效模式 |
| `动画预览.html` | 通用离线动画演示 |

压缩包不包含工作区已有的玩家存档、旧发布包、过时实验与 Python 缓存。旧文件已保留在工作区单独的 `归档/` 中，没有删除；原始 `uploads/` 未改动。

## 验证

发布包由 `tools/make_release.py` 生成，它在打包前强制校验 `版本清单.json` 全部哈希、`server.py` 为 ASCII-only、以及 `audit/final/meta.json` 记录的源码哈希与当前 `server.py` 一致；改动服务器源码后必须先重跑全池实战，否则打包会直接失败。

详见 `运行与验证.md`。当前已通过 519 项机制合同（逐卡核对）、29 项新机制定向断言（`tests/test_new_mechanics.py`）、18 组精确时序、满编随机战斗、8 视口布局回归和浏览器报告校验。完整报告中的实战结果基于记录的测试条件，不代表所有阵容都被穷举。

## 版本控制

项目纳入 Git 后，`.gitignore` 排除运行时玩家存档 `data/`、Python 缓存、测试截图与发布压缩包；`tools/make_release.py` 生成 `版本清单.json` 和压缩包时同样跳过 `.git/`，避免版本库元数据混入交付物。首次克隆后按「运行」一节启动即可，无需额外依赖。
