# OI-chess 最新版

**当前界面版本：ai-battle-1。** 本轮（**v1.8.0-ai-battle**）新增 **AI 对战**：创建房间时可直接选 **1~3 个电脑对手**（简单 / 普通 / 困难三档），房主也能在等待大厅点「+ 添加电脑」继续加人；选「不加电脑」仍是纯真人房。电脑在每个准备期自动买卡、布阵并点「准备」，**你点「准备」后全队立即开战**，一个人也能完整打一局。难度只改变电脑每回合愿意花多少钱、刷新几次商店、最多上阵多少棋子以及多爱凑同流派羁绊，**卡牌数值双方完全一致**；电脑使用独立随机流，不占用玩家档案、不参与 Rating，也不会改动卡牌战斗的随机结果。等待大厅、房间列表与对手栏都会显示「电脑」标签。CSS 与 JS 缓存版本均已同步为 `ai-battle-1`，更新后浏览器请按 Ctrl+F5 强制刷新。

此前一轮（**v1.7.4-ui-polish**）做了**整体视觉精修与信息可读性**优化：页面底与面板表面分层、纯黑细线改为柔和边框、面板/卡片/按钮加圆角与轻阴影、悬停与焦点反馈、棋盘网格线单独提对比、状态栏与卡面关键字号整体上调一档、羁绊档位效果改为独立 chip 分组并高亮激活态；浅色与深色主题同步适配。背景格线、点击格与棋子仍统一为 CSS Grid（详见 `docs/放置错位修复.md`），布局结构与棋盘对齐逻辑未改，8 视口 × 3 阶段布局回归与放置命中误差仍为 0。此前已修复半屏布局遮挡与商店卡片显示不全，并把卡牌从 35 张扩到 **50 张**、加入 6 种全新战斗机制与商店升星保底，以及启动前检查更新（**代理可选**：首次启动 `start.bat` 会询问一次直连还是走代理，选择保存在本地 `update_config.bat`，运行 `start.bat setup` 可重新选择；也可用环境变量 `OI_CHESS_PROXY=http://127.0.0.1:7890` 指定）。此前还新增了**技能去重与全局羁绊**：50 张卡改为 **50 种互不重复的技能**，新增按流派 2/4/6 档的**羁绊机制**，场上棋子上限从 15 提到 **20**；以及**准备期无倒计时**（全员点「准备」后立即开战）与**羁绊开战视觉反馈**。

上一轮（**v1.7.7-stdout-flush**）修掉启动窗口停在 `Exception ignored in: <_io.TextIOWrapper name='<stdout>' ...>` 的问题。这是解释器退出期自动 flush stdout 失败：缓冲区里还有中文输出，底层句柄却已被宿主/管道提前关闭，异常被 Python 忽略但窗口看起来像卡死。现在启动期每次输出都立即 flush，进程退出前再统一 flush 并吞异常，缓冲区始终为空。同时移除 `start.bat` 的 `chcp 65001` 与 `server.py` 的 `SetConsoleOutputCP(65001)`——Python 3.6+ 在 Windows 控制台通过 Unicode API 输出中文，与代码页无关，强切 65001 反而是这类控制台 IO 异常的来源；`PYTHONIOENCODING=utf-8:replace` 与 `_safe_print()` 继续为重定向和非中文代码页兜底。新增子进程回归，断言 stdout 句柄提前关闭时退出阶段不再产生该警告。

此前一轮（**v1.7.6-console-utf8**）修复 **Windows 启动崩溃**：部分非中文代码页的机器上，`chcp 65001` 后 `check_update.py` 与 `server.py` 的中文启动输出会抛 `UnicodeEncodeError`，导致检查更新非零退出、服务器根本起不来（选代理后直接回车尤其容易触发）。现在 `start.bat` 钉住 `PYTHONIOENCODING=utf-8:replace`，两个脚本对 stdout/stderr 统一 `reconfigure(utf-8, replace)` 并捕获全部异常，启动期输出全部走 `_safe_print()`——编码失败时自动降级为 `\uXXXX` 纯 ASCII 转义文本，绝不中断启动。新增 `tests/test_console_encoding.py` 用 cp1252 严格编码 + `reconfigure` 失效环境复现并守住该场景。游戏机制、卡牌数值与界面均未改动。

上一轮（**v1.7.5-maintainability**）是**项目治理与可维护性**更新，不涉及游戏机制与界面：新增 MIT `LICENSE` 与 GitHub Actions CI；`server.py` 改为 UTF-8 可读源码（4491 处 `\uXXXX` 反转义）、端口支持 `--port` / `OI_CHESS_PORT` 覆盖、三个巨型函数拆为分派表与 helper；删除工作区里的历史后端 `audit/before/`，改用只读数据快照；修正文档断言数与「仅标准库」表述，并写明可信局域网安全边界。改动前后 1150 场对局逐字段对比完全一致，59,200 场全池实战已按当前源码重跑。界面版本与 CSS/JS 缓存版本仍为 `ui-polish-1`，详见 `运行与验证.md`。

## Windows 启动

1. 完整解压文件夹，不要直接在压缩包中运行。
2. 双击 **`start.bat`**。
3. 如果需要手动启动，在本目录打开终端，执行：

```bat
py -3 server.py
```

也可以使用已确认指向 Python 3 的命令：

```bat
python server.py
```

建议使用 Python 3.10 或更新版本。**运行时零第三方依赖**（仅 Python 标准库）；回归测试中的浏览器用例需要额外安装 Playwright 与 Chromium，普通玩家启动游戏无需安装。启动后按终端提示访问网页。

端口默认 `8080`，可用 `--port 8123` 或环境变量 `OI_CHESS_PORT=8123` 覆盖。

> **安全边界**：服务端监听 `0.0.0.0`，当前身份模型是客户端自报 `clientId`，没有身份鉴权、CSRF 防护与频率限制，且允许跨域。**仅可在可信局域网内开黑使用，不要直接暴露到公网**；如需公网访问，必须置于带 TLS 与认证的反向代理之后。

**源码与编码：** `server.py` 使用 UTF-8 保存中文源码，入口会 reconfigure 标准输出；Windows 启动器只设置 `PYTHONIOENCODING=utf-8:replace` 供重定向场景兜底；控制台由 Python 通过 Unicode API 直接输出中文，不再切换代码页，Windows / Linux 均正常显示中文。平衡调整前的旧后端已移入 git history，工作区只保留 `audit/baseline/cards_before.json` 这份数据快照，不再有可误运行的旧源码。

## 当前版本关键数值

- **回合节奏**：准备期**无倒计时**，所有存活玩家点击「准备」后立即开战（左侧「准备 x/y」实时显示人数）；战斗 30s → 结算 → 下一回合。
- **O2 优化**：$3、攻击 0、生命 **280**；周围八格友军攻速 **×2**，同名不叠加。
- **SPFA**：$3、攻击 **120**、生命 **1000**；攻速 ×1.5、普攻伤害 ×1.2，每次普攻后独立 20% 概率额外停攻 4 秒。
- **升星**：3 张同名同星棋子自动合成，最高 3 星；生命/攻击每星 **×1.8**（3 星 ×3.24）。2/3 星卖出返还 3/9 份金币再减 1，合成后满血。光环类效果不随星级增强，同名光环始终不叠加；升星只提高生命与攻击，O2 优化攻击 0 升星后仍为 0。
- **商店与卡池**：每轮第一次刷新免费，第二次 **2 金**，之后每次 **+1 金**（2/3/4…），棋子本身价格不变。卡池按等级解锁费用（等级 L 可出 1–L 费，低费权重更高；等级 1 仍是纯 1 费，与旧版一致）；每轮结算赠送的一张卡同样从当前等级卡池抽取，不再开局白送 5 费核心。等级每两轮 +1，第 9 轮达到 5 级；差一张即可合成的卡在商店与赠送卡中权重 ×4（升星保底），缓解 50 张卡池的稀释。
- **小轮结算**：阵亡棋子不再消失，保留到下一轮并按原有恢复规则复活；按双方存活棋子的星级之和判定胜负，败者 HP 减少双方星级之和的差，HP 归零即出局。
- 攻击采用精确事件计时，不再将普攻间隔向上取整到 0.5 秒。
- **状态轮询**：请求携带版本号，房间版本与聊天版本均未变时服务端只返回计时字段（8 人满编全量约 3.5 KB，瘦响应约 190 B），心跳与倒计时精度不变；版本或聊天一变立即回退到全量快照。
- **半屏布局**：FX / 主题 / 退出按钮改为顶部独立工具条，不再浮在商店与状态栏上；窄屏状态栏固定属性条宽度并隐藏版本号小字，矮屏自动压薄聊天区把高度还给棋盘；战斗棋盘从首帧即为合并 8×8，杜绝半场被裁；商店卡宽自适应并给列表加明确的细滚动条，窄屏商店行固定高度避免把棋盘压没。8 视口 × 3 阶段由 `tests/test_layout.py` 回归。
- **场上与备战上限**：场上棋子由 15 提到 **20** 个（4×8 共 32 格，容得下），备战席仍为 **10** 张。
- **羁绊**：按流派统计**自己场上**的棋子数量，达到 **2 / 4 / 6** 张逐档激活——档位 1 同流派棋子攻击 **+6%**，档位 2 再加生命 **+8%**，档位 3 再加承伤 **-6%**。只统计己方棋子，对手不计入；生命加成按整数结算，避免浮点截断。左侧状态栏实时显示各流派数量、当前档位与距离下一档还差几张；战斗开场会弹出「羁绊激活」提示，己方同流派棋子左上角有档位点亮徽标。
- 已完成全卡机制核对、九张卡数值调整、实战定位与清晰特效更新；此前补上按等级解锁的卡池与半屏布局修复。本轮把 50 张卡改为 50 种独立技能、加入全局羁绊并把上场上限提到 20，全池实战数据已按当前源码重跑。

## 技能去重与全局羁绊

卡池仍是 **50 张**（ID、名称、费用、基础攻防、流派、定位全部保留），但每张卡的技能**互不重复**。此前 50 张卡只有 38 种技能（`synergy` 4 张、`pierce` 3 张，另外 9 种各 2 张），本轮把重复的技能全部换成与该算法特点相符的独立机制。

**新增的 13 种独立技能**：

| 技能 | 载体卡 | 效果 |
|---|---|---|
| 前缀累计 `prefix_growth` | 前缀和 | 每命中一次攻击 +10%，最多 6 层（+60%） |
| 最小生成树链 `mst_link` | 最小生成树 | 正交相邻友军每条边减伤 6%，最多 4 边（-24%） |
| 强连通标记 `scc_mark` | 强连通分量 | 被打过的目标每层承伤 +8%，最多 3 层 |
| 蝶形变换 `fft_butterfly` | 快速傅里叶变换 | 奇数击 ×0.75 / 偶数击 ×1.7 |
| KMP 跃迁 `kmp_next` | KMP | 未击杀每击 +10%（最多 5 层），击杀即清零 |
| 最长公共前缀 `lcp_chain` | 后缀数组 | 连打同名 ×1.5，一换目标掉到 ×0.8 |
| 线段树区间查询 `seg_query` | 线段树 | 每第 4 击对射程内其余全体追加 60% 伤害 |
| 启发式选点 `heuristic` | A* | 估价挑低血目标，且所有伤害 +25% |
| 模周期振荡 `mod_cycle` | 费马小定理 | 7 击一循环：×1.3 逐击衰减到 ×0.4，末击 ×2.0 |
| 伸展旋转 `splay_rotate` | 伸展树 | 每击 +7% 攻击（最多 6 层），自己受伤立刻折半 |
| 最小割 `min_cut` | 网络流 | 射程内全体分摊伤害，血量最高者再吃一刀最大流 |
| 多模式匹配 `multi_match` | AC 自动机 | 额外同名敌人各吃 30% |
| 自动机压缩 `sam_compress` | 后缀自动机 | 每有一名同名友军就多一份攻击状态；合并状态会挤占生命上限（独苗不扣血） |

**负面技能用于限制高基础数值卡**：模周期振荡、最长公共前缀、蝶形变换三条技能自带惩罚段（下一击更低），自动机压缩用「攻击换生命上限」换取构筑收益，伸展旋转在受伤时清空层数。上一轮的新卡专属「协同 `synergy`」被全局羁绊取代。

**全局羁绊**取代了专属协同：

| 档位 | 同流派张数 | 效果 |
|---|---|---|
| 1 | 2 张 | 同流派棋子攻击 +6% |
| 2 | 4 张 | 再加生命 +8% |
| 3 | 6 张 | 再加承伤 -6% |

只统计**自己场上**的棋子，对手棋子不计入；生命加成按整数结算。左侧状态栏有实时羁绊面板，图鉴顶部也给出说明。

前端同步补齐 50 种技能的中文标签、图鉴技能名与羁绊面板；羁绊的档位与生效效果由服务端 `bond_status()` 计算，前端只负责展示。


## 检查更新

每次通过 **`start.bat` 启动前**会先运行 `check_update.py`，对比 GitHub 上的最新 Release；浏览器打开主菜单时也会静默检查一次（同一会话只查一次）。发现新版本时，终端打印发布页与下载链接，主菜单顶部出现一条可关闭的提示条。

设计约束：

- **只提示，不自动下载、不覆盖文件**。自动更新会破坏交付包的可复现性，也可能碰到玩家存档 `data/`。
- **离线优先**：默认 2.5 秒超时（浏览器 4 秒），DNS 失败、超时、限流、JSON 异常一律静默跳过，退出码恒为 0，绝不阻塞启动。
- **不参与轮询**：检查只在启动时执行一次，与每 300ms 的 `/api/state` 瘦响应完全解耦。
- **版本真相源**：本地 Release 版本写在 `static/index.html` 的 `<meta name="oi-chess-release">`，`check_update.py`、`版本清单.json` 的 `release_tag` 与浏览器端都从这里读取，由 `tests/test_update_check.py` 断言一致。
- **版本号比较**：只比较 `vMAJOR.MINOR.PATCH` 的前三段数字；远程严格大于本地才提示。本地是开发版（比远程新）或同版本不同构建都不误报。

| 环境变量 | 作用 |
|---|---|
| `OI_CHESS_SKIP_UPDATE=1` | 完全跳过启动器检查 |
| `OI_CHESS_UPDATE_TIMEOUT=2.5` | 调整网络超时（秒） |

直接执行 `py -3 server.py` 会跳过终端检查（浏览器端仍会检查），官方入口仍是 `start.bat`。手动检查可运行 `py -3 check_update.py --json`，输出机器可读的状态字典。

## 验证

发布包由 `tools/make_release.py` 生成，它在打包前强制校验 `版本清单.json` 全部哈希、`server.py` 为合法 UTF-8、以及 `audit/final/meta.json` 记录的源码哈希与当前 `server.py` 一致；改动服务器源码后必须先重跑全池实战，否则打包会直接失败。

详见 `运行与验证.md`。当前已通过 530 项机制合同（逐卡核对）、79 项新机制定向断言（`tests/test_new_mechanics.py`）、18 组精确时序、满编随机战斗、8 视口布局回归和浏览器报告校验。完整报告中的实战结果基于记录的测试条件，不代表所有阵容都被穷举。

`.github/workflows/ci.yml` 把上述验证拆成两个任务：`stdlib` 跑 14 个纯标准库测试、`py_compile`、`node --check` 与 `tools/make_release.py` 发布闸门；`browser` 安装 Playwright / Chromium 后跑 6 个浏览器回归。push 到 `main`、Pull Request 与手动触发时自动执行。本地已用同一套命令跑完全部 21 项回归。

## 版本控制

项目纳入 Git 后，`.gitignore` 排除运行时玩家存档 `data/`、Python 缓存、测试截图与发布压缩包；`tools/make_release.py` 生成 `版本清单.json` 和压缩包时同样跳过 `.git/`，避免版本库元数据混入交付物。首次克隆后按「运行」一节启动即可，无需额外依赖。仓库采用 **MIT 授权**（见 `LICENSE`）；`.github/workflows/ci.yml` 提供 push / PR 自动回归。
